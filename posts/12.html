Arch Linux 从零入门：安装原理、可复制流程与滚动更新的长期维护

技术 2026-11-13
Arch LinuxLinuxpacman系统安装滚动更新AUR

Arch Linux 的安装教程多到泛滥，但大多数只是把官方 Wiki 的命令抄一遍，读者照做能装好，却不知道每一步在系统里究竟改了什么。一旦遇到「开机没有引导项」「更新后黑屏」「签名校验失败」，就只会重装。

这篇按原理 → 可复制流程 → 长期维护三段组织：先讲清 Arch 的设计取舍和 UEFI 启动链，再给出一条完整安装命令链并逐段解释，最后讲滚动发行版真正难的部分——怎么让它稳定运行三年而不是三天。

一、先判断 Arch 适不适合你

Arch 的核心不是「难」，而是把选择权全部交还给用户：安装盘只提供最小环境，没有默认桌面、没有默认分区方案、没有预装驱动。代价是你要理解自己在做什么；收益是系统里没有你不想要的东西。

维度ArchDebian / UbuntuFedora
发布模型滚动更新，无版本号升级固定版本 + 定期大版本升级约 6 个月一个版本
包版本接近上游最新偏保守，重视稳定较新但经过集成测试
初始状态命令行最小系统安装器给完整桌面安装器给完整桌面
软件来源官方仓库 + AUR（社区 PKGBUILD）apt 仓库 + PPAdnf 仓库 + COPR
维护成本需关注 News、处理 pacnew低中

适合：想搞懂 Linux 各层如何拼装、需要新内核/新驱动、愿意读文档并定期维护的人。不适合：把它当生产服务器却不打算看公告、或者希望装完两年不管的机器。滚动更新最怕的不是更新本身，而是长期不更新然后一次性跨半年。

二、安装前：准备与心智模型

  • 镜像：只从 archlinux.org 官方下载页取 ISO，并核对 SHA256 与 PGP 签名。Get-FileHash 可算哈希；镜像被篡改在这个环节就能挡住。
  • 启动盘：UEFI 机器上用 Ventoy 或 Rufus（GPT + FAT32）写入即可。若装机时 Secure Boot 拦住，临时关闭；Arch 官方安装介质默认不带签名支持。
  • 固件：确认是 UEFI 而非 Legacy/CSM，目标盘用 GPT。Windows 双系统还需先在系统里关闭快速启动，并准备好共享同一个 EFI 系统分区（千万不要重新格式化已有 ESP，那会抹掉 Windows 引导）。
  • 数据：整盘安装会清空目标磁盘。先备份到另一块物理介质，并确认能读出来。
  • 网络：安装过程全程联网。有线最省事；只有 Wi-Fi 时准备用 iwctl。
  • 时间：系统时间错误会导致 HTTPS 证书与包签名校验失败，所以联网后第一件事是同步时钟。

启动链：理解每一步在安装什么

UEFI 固件
  → 读取 ESP(FAT32) 里的引导程序  bootx64.efi / systemd-boot / grubx64.efi
  → 引导程序加载 内核 vmlinuz-linux + initramfs
  → 内核按 root= 参数挂载真正的根分区
  → 启动 PID 1 (systemd) → 进入用户空间

于是安装动作可以归为四组：① 建分区并格式化（给内核一个家）、② 用 pacstrap 把包解压进目标根（装系统文件）、③ 写 fstab / locale / hostname（告诉系统怎么挂载、怎么显示）、④ 安装并配置引导器（让固件找得到内核）。少任何一组都起不来。

分区规划（UEFI / GPT）

分区建议大小文件系统挂载点说明
EFI 系统分区1 GiBFAT32/boot用 systemd-boot 时内核也放这里，300 MiB 容易不够；双系统复用已有 ESP
swap视内存与休眠需求swap—要休眠需不小于物理内存；也可用 swapfile 或 zram
根分区剩余空间ext4 / btrfs/btrfs 可做快照回滚，代价是配置更复杂

三、完整安装流程（UEFI + systemd-boot）

以下命令可直接照抄，但请把 /dev/nvme0n1 换成你的实际磁盘。先用 lsblk -f 看清型号与容量，选错盘会不可逆地清空数据。

# ① 确认以 UEFI 64 位启动（输出 64）
cat /sys/firmware/efi/fw_platform_size

# ② 联网：有线通常自动 DHCP；Wi-Fi 用 iwctl 交互
iwctl
#   device list
#   station wlan0 scan
#   station wlan0 get-networks
#   station wlan0 connect "YOUR-SSID"
#   exit
ping -c 3 archlinux.org

# ③ 同步时钟（影响证书与签名校验）
timedatectl set-ntp true
timedatectl status

# ④ 选一个快的镜像（可选，但显著影响安装速度）
reflector --country China --age 12 --protocol https --sort rate --save /etc/pacman.d/mirrorlist

# ⑤ 分区（按上表建 3 个分区）
lsblk -f
cfdisk /dev/nvme0n1

# ⑥ 格式化与挂载：顺序不能反，先挂根再挂 ESP
mkfs.fat -F 32 /dev/nvme0n1p1
mkswap /dev/nvme0n1p2
mkfs.ext4 /dev/nvme0n1p3
swapon /dev/nvme0n1p2
mount /dev/nvme0n1p3 /mnt
mount --mkdir /dev/nvme0n1p1 /mnt/boot

# ⑦ 安装基本系统（-K 初始化目标环境的 pacman 密钥环）
pacstrap -K /mnt base linux linux-firmware intel-ucode \
  networkmanager sudo vim bash-completion
# AMD CPU 把 intel-ucode 换成 amd-ucode；虚拟机可省微码包

# ⑧ 生成 fstab（用 UUID 而非设备名，避免插拔盘后错位）
genfstab -U /mnt >> /mnt/etc/fstab
cat /mnt/etc/fstab          # 务必人工看一眼再继续

# ⑨ 切入新系统，此后所有操作都发生在目标盘上
arch-chroot /mnt
base 元软件包不包含内核、编辑器、网络管理工具和引导器，只提供最基础的 POSIX 环境。这是新手最常踩的坑：装完重启发现没有内核可引导，或没有网络工具可用。上面把它们显式列进 pacstrap 了。
# ⑩ 时区与本地化
ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime
hwclock --systohc
vim /etc/locale.gen        # 取消 en_US.UTF-8 UTF-8 与 zh_CN.UTF-8 UTF-8 的注释
locale-gen
echo "LANG=en_US.UTF-8" > /etc/locale.conf
echo "KEYMAP=us" > /etc/vconsole.conf

# ⑪ 主机名与 hosts
echo "arch" > /etc/hostname
# /etc/hosts 写入三行：
# 127.0.0.1   localhost
# ::1         localhost
# 127.0.1.1   arch.localdomain arch

# ⑫ 网络、root 密码与普通用户
systemctl enable NetworkManager
passwd
useradd -m -G wheel,storage,power -s /bin/bash alex
passwd alex
EDITOR=vim visudo          # 取消注释 %wheel ALL=(ALL:ALL) ALL

建议日常使用普通账户 + sudo，不要长期以 root 登录桌面。wheel 组授权是 Arch 的标准做法。

# ⑬ 重生成 initramfs（若改过 mkinitcpio.conf、用 btrfs/LVM/加密则必做）
mkinitcpio -P

# ⑭ 安装引导器：ESP 已挂在 /boot，systemd-boot 可直接用
bootctl install

# /boot/loader/loader.conf
default  arch.conf
timeout  4
console-mode max
editor   no

# /boot/loader/entries/arch.conf
title    Arch Linux
linux    /vmlinuz-linux
initrd   /intel-ucode.img
initrd   /initramfs-linux.img
options  root=UUID=这里填根分区UUID rw

根分区 UUID 用 blkid -s UUID -o value /dev/nvme0n1p3 取得。两个 initrd 行的顺序不能反：微码必须在主 initramfs 之前加载。editor no 防止任何人在启动菜单里直接追加 init=/bin/bash 绕过认证。

# ⑮ 退出、卸载、重启（拔掉安装盘）
exit
umount -R /mnt
reboot

若更习惯 GRUB（例如需要多系统自动探测），把 ⑬⑭ 换成：

pacman -S grub efibootmgr os-prober
grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB
grub-mkconfig -o /boot/grub/grub.cfg

GRUB 还需在 /etc/default/grub 里开启 GRUB_DISABLE_OS_PROBER=false 才能识别 Windows。官方还提供 archinstall 交互式脚本，适合理解了流程之后快速复装；第一次仍建议手动走一遍，因为排查能力来自知道每一步改了什么。

四、第一次启动后：把最小系统变成可用系统

sudo pacman -Syu                         # 先全量同步一次

# 显卡（按硬件选其一，别全都装）
sudo pacman -S mesa xf86-video-amdgpu   # AMD / Intel 核显
sudo pacman -S nvidia nvidia-utils      # NVIDIA 闭源驱动

# 声音与蓝牙
sudo pacman -S pipewire pipewire-pulse wireplumber
sudo pacman -S bluez bluez-utils
sudo systemctl enable --now bluetooth

# 中文字体与输入法
sudo pacman -S noto-fonts-cjk fcitx5-im fcitx5-chinese-addons

# 桌面环境（二选一）与显示管理器
sudo pacman -S gnome gdm                # 或 plasma sddm
sudo systemctl enable gdm

输入法是新手最容易卡住的一环：装完包还需要在 /etc/environment 写入 GTK_IM_MODULE=fcitx5、QT_IM_MODULE=fcitx5、XMODIFIERS=@im=fcitx5，并在桌面会话里把 fcitx5 加入自启动、用 fcitx5-configtool 添加拼音引擎。

NVIDIA 用户还要注意：Wayland 会话需要内核参数 nvidia_drm.modeset=1（写进上面 arch.conf 的 options 行），且闭源驱动与内核版本严格绑定，更新内核时务必确认 nvidia 与 linux 同步升级。

五、pacman：日常维护的核心纪律

命令作用要点
pacman -Syu同步数据库并全量升级唯一推荐的升级方式；永远不要单独 -Sy 后装包
pacman -S pkg安装包数据库过旧时先 -Syu
pacman -Rns pkg删包 + 无用依赖 + 配置比 -R 干净
pacman -Ss / -Qs搜远程仓库 / 本地已装配合 -Qi 看包详情、-Ql 看文件清单
pacman -Qdt列出孤儿包定期清理，但先确认不是刻意保留的可选依赖
pacman -Qo /path/f查某文件属于哪个包排查文件冲突、定位配置来源
pacman -Fy 后 -Fs f查未安装文件在哪个包常见于「缺某个命令/库」
paccache -r清理包缓存（保留最近版本）来自 pacman-contrib；-rk2 保留最近 2 版以便降级
pacman -U 包路径从本地缓存安装指定版本回滚主力手段
部分升级是 Arch 最常见的自毁方式。执行 pacman -Sy 刷新数据库后只装一个包，会让新包依赖的新版库没被一起升级，系统进入半新半旧的混合状态。永远用 -Syu 一次完成，AUR helper 也别配成 -Sy 开头。

AUR：便利与风险同源

AUR 里不是编译好的包，而是社区维护的 PKGBUILD——一段会以你的权限执行的 shell 脚本。用 helper 之前，建议至少手动走一次：

sudo pacman -S --needed base-devel git
git clone https://aur.archlinux.org/paru.git
cd paru
less PKGBUILD          # 审阅：来源 URL、校验和、install 脚本、有无可疑命令
makepkg -si

之后可用 paru -S 包名。原则：优先官方仓库；AUR 包升级后要重新审阅变更；不要以 root 运行 makepkg；遇到需要手动干预的公告时先处理再更新。

六、滚动更新的长期维护

  1. 升级前看官网 News。Arch 首页会标注「需要手动干预」的变更（配置文件格式改了、包拆分了、某些操作必须按顺序做）。跳过这一步是绝大多数升级事故的根因。
  2. 保持节奏：每一到两周 pacman -Syu 一次。跨度越大，累积的配置迁移越难处理。
  3. 处理 .pacnew / .pacsave：包升级时若你改过配置，新配置会落成 .pacnew 而不是覆盖。用 pacdiff -s（pacman-contrib）或 find /etc -name '*.pac*' 找出并合并，长期不处理会导致服务启动异常。
  4. 备一个 LTS 内核：sudo pacman -S linux-lts linux-lts-headers，并在引导器里加一条独立启动项。主线内核出问题时可从菜单切到 LTS 兜底，不必依赖 Live USB。
  5. 做快照：根分区用 btrfs + snapper（或 Timeshift），配合 grub-btrfs 直接从引导菜单回滚。这是滚动发行版性价比最高的一笔投资。
  6. 保留包缓存：paccache -rk2，让 /var/cache/pacman/pkg 里留着上一版，出问题时 pacman -U 直接降级。
  7. 知道怎么救：进不了系统时用安装 U 盘启动，mount + arch-chroot 回去重装内核、重跑 mkinitcpio -P、或降级有问题的包。

七、排障对照表

现象根因处理
开机固件里没有 Arch 启动项bootctl install 未写入 NVRAM，或 ESP 挂错位置用安装盘 chroot 后重跑 bootctl install；确认 ESP 挂载到 /boot
进系统卡在黑屏 / 只有光标显卡驱动与内核版本不匹配、KMS 时序、缺微码引导项临时加 nomodeset；切 LTS 内核；核对 initrd 顺序
pacman -Syu 大量 404镜像过期或数据库不一致reflector 重生成 mirrorlist 后 pacman -Syyu
GPG 签名校验失败archlinux-keyring 过旧、系统时间错误先 timedatectl set-ntp true；再 pacman -Sy archlinux-keyring 后 -Syu
装完没有网络只装了 base，未启用 NetworkManagerchroot 回去 systemctl enable NetworkManager，重新 nmcli dev wifi connect
中文显示为方块缺 CJK 字体或 locale 未生成装 noto-fonts-cjk；确认 locale.gen 已取消注释并跑过 locale-gen
更新后某服务起不来.pacnew 未合并、配置格式变更pacdiff -s 合并；查 journalctl -xeu 服务名
AUR 包构建失败缺 base-devel、PGP 公钥、或上游 URL 失效装 base-devel；按 PKGBUILD 里的指纹 gpg --recv-keys；检查校验和
根分区被占满包缓存与 journal 累积paccache -r、journalctl --vacuum-size=200M、pacman -Qdt 清孤儿包
双系统 Windows 消失ESP 被重建或 os-prober 未开启GRUB 里开 GRUB_DISABLE_OS_PROBER=false 再 grub-mkconfig；ESP 被格式化则需修复 Windows 引导

八、操作前检查清单

  • ISO 已核对 SHA256 / 签名，来自官方渠道；
  • 目标磁盘型号已用 lsblk 二次确认，重要数据已备份到另一块物理介质；
  • 已确认 UEFI + GPT，双系统已关闭 Windows 快速启动、不会重建 ESP；
  • 安装环境联网可用，时钟已同步；
  • 已想清楚文件系统（ext4 简单 / btrfs 可快照）、swap 策略与是否需要休眠；
  • 引导器方案已定，微码包与 CPU 匹配，root= 的 UUID 已核对；
  • 已准备好普通用户与 sudo，未在桌面长期用 root；
  • 知道出问题如何用安装 U 盘 arch-chroot 回去修复。

结语

Arch 真正的入门门槛不在命令长度，而在建立一个「每一层由谁负责」的模型：固件找引导器、引导器加载内核、内核按 fstab 与 root 参数挂载、systemd 拉起服务、pacman 维护用户空间。理解这条链之后，安装只是把部件按序放好，排障也只是沿链定位。

建议第一次在虚拟机里完整装两遍：一遍照抄，一遍刻意删掉引导项再用安装盘救回来。演练过恢复流程，再装到物理机才不会手忙脚乱。后续遇到任何问题，Arch Wiki 的优先级高于任何博客——包括这篇。
