Python 装饰器详解：从 @ 语法到实战应用

技术 2026-11-11
Python装饰器进阶元编程

Python 装饰器（Decorator）看起来只是一个 @ 符号，背后却是函数式编程与元编程的精华。它能在不修改原函数代码的前提下，给函数「套上」额外行为——计时、缓存、鉴权、日志统统用它。本文从最直观的例子讲起，一直到带参装饰器、类装饰器和真实应用场景。

1. 什么是装饰器

在 Python 里，函数是一等公民：可以赋值给变量、当作参数传递、作为返回值。装饰器正是利用这一点——它本质是一个接收函数、返回函数的可调用对象。所谓「装饰」，就是把原函数包一层，再返回包装后的函数。

2. 第一个装饰器：给函数计时

import time

def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.time() - start:.4f}s")
        return result
    return wrapper

@timer
def slow_add(a, b):
    time.sleep(0.5)
    return a + b

slow_add(1, 2)

wrapper 用 *args, **kwargs 接住任意参数，调用原函数后再打印耗时，最后把结果原样返回——原函数「长什么样」没变，只是多了一层计时。

3. @ 语法糖

@timer 只是下面写法的简写：

def slow_add(a, b):
    time.sleep(0.5)
    return a + b
slow_add = timer(slow_add)

也就是说，@装饰器 放在函数定义上方，等价于「把下面这个函数传给装饰器，再把返回值绑回原名」。

4. 保留原函数信息：functools.wraps

上面那个装饰器有个隐患：包装后 slow_add.__name__ 会变成 wrapper，原函数的名字和文档都丢了，影响调试和自动文档。用 functools.wraps 修正：

import functools, time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.time() - start:.4f}s")
        return result
    return wrapper

@functools.wraps(func) 会把原函数的 __name__、__doc__ 等元信息复制给 wrapper，这是写装饰器的标准动作。

5. 带参数的装饰器

想让装饰器本身也能接收参数（比如「重复执行 N 次」），需要再多包一层：

import functools

def repeat(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(times=3)
def greet(name):
    print(f"Hello, {name}")

greet("World")  # 打印 3 次

结构是「参数层 → 装饰器层 → 包装层」三层嵌套，记住这个套路就不容易写错。

6. 类装饰器

装饰器不一定是函数，只要是可调用对象即可。用类实现时，把原函数存起来，在 __call__ 里执行包装逻辑：

class CountCalls:
    def __init__(self, func):
        self.func = func
        self.calls = 0

    def __call__(self, *args, **kwargs):
        self.calls += 1
        print(f"第 {self.calls} 次调用")
        return self.func(*args, **kwargs)

@CountCalls
def say_hi():
    print("hi")

say_hi()
say_hi()

7. 真实应用场景

  • 缓存：functools.lru_cache 缓存函数返回值，斐波那契这类递归瞬间提速。
  • 属性：@property 把方法变成可读属性，调用时像访问字段。
  • Web 路由：Flask 的 @app.route("/") 用装饰器把函数注册成 URL 处理器。
  • 鉴权与日志：在接口函数外包一层登录校验或访问日志，业务代码保持干净。
from functools import lru_cache

@lru_cache(maxsize=128)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

8. 常见坑

  • 忘了 @functools.wraps：原函数名、文档丢失，调试和文档生成会出问题。
  • 执行时机：装饰器的外层在定义时（import 时）就执行，而不是函数被调用时——别在里面放耗时或依赖运行时状态的逻辑。
  • 多层装饰器：从下往上执行，离函数最近的先包，顺序容易让人迷糊，建议逐个加、逐个测。
  • 参数层漏写：带参装饰器少包一层是最常见错误，牢记三层结构。

结语

装饰器的魅力在于「开闭原则」：对扩展开放、对修改关闭。学会它，你就能把横切关注点（计时、缓存、鉴权、日志）从业务代码里抽出来，让每个函数只关心自己的事。从手写一个 timer 开始，再逐步用到 lru_cache 和框架里的路由装饰器，你会越来越体会到它的优雅。
