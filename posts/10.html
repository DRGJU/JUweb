像高手一样用基础网络命令：排查连通性、看懂网络环境

技术 2026-11-12
网络命令行排障网络诊断Windows

网络出问题时，很多人只会反复刷新或重启路由器。真正的高手，靠的是一组基础命令，把"网络坏了"这种模糊的感受，拆解成"哪一段、哪一层、谁的责任"。本文带你系统过一遍最常用、也最被低估的网络命令，并给出判断网络环境的实用框架。

一、先建立心智模型：网络分几层

在敲命令前，先记住四个检查点，绝大多数故障都落在这四者之一：

  • 本机：网卡是否启用、IP / 网关 / DNS 是否正确；
  • 局域网网关：能不能到路由器（通常是 192.168.x.1）；
  • 运营商 / 公网：能不能出网、有没有被限速或断网；
  • 远端目标：对方服务器是否在线、端口是否开放、DNS 是否解析得到。

排查的顺序，就是从近到远一层层往外推。

二、基础命令清单（按场景）

1. ping —— 连通性与延迟

最基础也最有用。看三件事：能不能通、往返延迟多少、有没有丢包。

ping -t 1.1.1.1        # Windows 持续 ping，Ctrl+C 停止
ping -c 10 8.8.8.8     # macOS / Linux 发 10 个包

经验值：局域网延迟通常 < 3ms，同城宽带 < 30ms，跨省 / 跨国 50–150ms 都属正常；丢包率超过 1% 就该警惕，超过 5% 基本不可用。

高手技巧：同时开两个窗口，一个 ping 1.1.1.1（纯连通性），一个 ping www.example.com（含 DNS）。前者通、后者不通，问题就在 DNS，而不是网络。

2. ipconfig / ip —— 看清本机与网关

ipconfig /all                    # Windows 看 IP、网关、DNS
ip addr show                    # Linux 看网卡与地址
ip route show                   # 看默认网关与路由表

重点看：是否拿到了正确的 IPv4 地址（不是 169.254 开头的 APIPA 自分配）、默认网关是否非空、DNS 服务器是否可达。

3. tracert / traceroute —— 看清路径

当 ping 不通或很慢，用路径追踪定位"卡在第几跳"。

tracert 8.8.8.8        # Windows
traceroute 8.8.8.8     # macOS / Linux

如果前几跳（本机到网关）就 * * *，是局域网问题；如果一直走到运营商骨干才丢，多半是对端或骨干拥塞。

4. nslookup / dig —— 排查 DNS

nslookup www.example.com 8.8.8.8   # 指定用公共 DNS 解析
dig @1.1.1.1 www.example.com      # Linux / macOS 更详细

能解析但慢，可能是本地 DNS 污染或上游不稳定；彻底解析不出，先换公共 DNS（如 1.1.1.1 / 8.8.8.8）验证。

5. netstat —— 看连接与端口

netstat -ano | findstr :443      # Windows 看谁占了 443 端口
netstat -tunlp                   # Linux 看监听端口与进程

配合任务管理器或 tasklist，能定位"哪个程序偷偷在联网"。

6. curl / Test-NetConnection —— 测端口与 HTTP

curl -I https://www.example.com     # 只看响应头，快速判断服务状态
Test-NetConnection 8.8.8.8 -Port 443   # PowerShell 测端口通不通

curl 的 -I 只看头部，比下载整个页面快得多，适合判断 Web 服务是否活着。

三、像高手一样判断网络环境

命令只是工具，真正的判断力来自这几个维度：

  • 延迟：越低越好，但要结合距离看，跨国 100ms+ 不必大惊小怪；
  • 丢包：> 1% 开始影响体验，> 5% 视频会议会卡死；
  • 抖动（jitter）：延迟忽高忽低比单纯高延迟更伤实时应用；
  • 对称性：上传远小于下载是常态，但如果上传也满速，可能在被限速或中招。

另外要学会识别"环境类型"：拿到的是公网 IP 还是 NAT / CGNAT（运营商常把多人塞进一个出口 IP），这决定了你能否做端口映射、远程访问。用 curl ifconfig.me 看到的 IP，如果和你路由器 WAN 口一致，才是真公网。

四、一套可复用的排障顺序

  1. 本机自检：网卡启用？IP / 网关 / DNS 正常？ipconfig /all
  2. 到网关：ping 192.168.1.1，不通先查网线 / Wi-Fi；
  3. 到公网：ping 1.1.1.1，不通是运营商问题；
  4. 到 DNS：ping www.baidu.com，不通换 DNS；
  5. 到目标端口：Test-NetConnection 主机 -Port 端口，判断是服务挂了还是被拦截。

每一步都能把问题收束到具体一层，避免无头苍蝇式重启。

五、安全提示

本文命令都是只读诊断，不会改动系统。但要注意：不要把 ping / tracert 对一个你不拥有的服务器刷太猛，可能被当成攻击；在公共网络里，别用明文协议传密码，优先 HTTPS / SSH。

把这些命令串成"由近及远"的排查链路，你就能在别人还在重启路由器时，已经定位到是哪一跳出了问题。
