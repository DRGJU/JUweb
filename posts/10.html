像高手一样用基础网络命令：分层排查框架与网络环境判读

技术 2026-11-12
网络命令行排障TCP/IP网络诊断Windows

网络不通时，多数人的做法是随手 ping 一下百度，通了就说「网络没问题」，不通就重启路由器。真正拉开差距的不是记住多少命令，而是脑子里有没有分层框架：一次访问要穿过五层，每层有对应的命令与典型故障。定位就是由近及远，逐层排除。

一、分层排查框架

① 本机配置   IP / 掩码 / 网关 / DNS / 网卡状态   ipconfig, ip addr
② 链路与网关 能不能到隔壁、能不能到网关        ping 网关, arp
③ 路由与连通 出不出得去、在哪一跳断掉          tracert, pathping, mtr
④ 名称解析   域名能否变成 IP、被解析到哪       nslookup, dig
⑤ 传输与应用 端口通不通、TLS 与 HTTP 是否正常   Test-NetConnection, curl -v
核心原则：先测 IP 再测域名，先测近处再测远处。直接 ping 域名失败时，你无法区分是「网络断了」还是「DNS 坏了」——用 ping 223.5.5.5 一测就能切开。

二、第 ① 层：把本机配置看全

# Windows
ipconfig /all                        # 完整配置：IP、网关、DNS、DHCP、租约
Get-NetIPConfiguration -Detailed     # PowerShell，按接口聚合更清晰
route print                          # 路由表，重点看 0.0.0.0/0 默认路由
arp -a                               # 邻居表，确认网关 MAC 是否解析到

# Linux / macOS
ip addr show                         # 地址
ip route show                        # 路由
ip neigh show                        # 邻居（替代 arp）
resolvectl status                    # 当前实际生效的 DNS

这一层要看的不是「有没有 IP」，而是四件事：是否拿到 169.254.x.x（APIPA，说明 DHCP 失败）、默认网关是否存在且可达、DNS 指向谁（公司内网、运营商、还是被改成奇怪的公网地址）、掩码是否正确（掩码错会造成本网段都 ping 不通）。另外留意多网卡、VPN、Docker 虚拟网卡带来的多条默认路由——route print 里跃点数（metric）最小的那条才是实际出口。

三、第 ② ③ 层：ping 与 traceroute 的原理

ping 到底在测什么

ping 发的是 ICMP Echo Request，属于网络层，跟 TCP 端口、HTTP 服务毫无关系。所以：

  • ping 不通 ≠ 网络不通：很多主机与防火墙主动丢弃 ICMP，但 80/443 服务好好的。反过来，能 ping 通也不代表应用可用。
  • ping 的 RTT 是往返时延，包含排队与对端处理；别拿它当单向链路质量。
  • 「请求超时」和「目标主机不可达」是两回事：后者通常由某台路由器明确回了一个 ICMP 不可达报文，反而说明路径是通的。
ping -n 20 example.com               # Windows 发 20 个包，看丢包率与抖动
ping -c 20 example.com               # Linux/macOS
ping -f -l 1472 example.com          # Windows 不分片探测 MTU
ping -M do -s 1472 example.com       # Linux 等价写法

MTU 探测是排查「网页打不开但 ping 正常、小文件能传大文件卡死」的关键。-l 1472 加上 28 字节 IP/ICMP 头正好 1500；若报「需要拆分数据包但设置 DF」，逐步减到能通为止，就能定位 PPPoE、VPN、隧道造成的 MTU 收缩。

traceroute：TTL 如何画出路径

它依次发出 TTL=1、2、3… 的包，每经过一跳路由器 TTL 减到 0，路由器回一个 ICMP Time Exceeded，于是我们就知道这一跳是谁。

tracert example.com        # Windows（默认 ICMP）
traceroute example.com     # Linux（默认 UDP，可加 -I 用 ICMP、-T 用 TCP）
pathping example.com       # Windows：先追路径，再对每跳统计丢包
mtr -rwzc 100 example.com  # Linux：持续采样，最适合抓间歇性丢包
现象怎么读
中间几跳全是 * * *该路由器不回 ICMP 超时报文。只要后面又能出现跳数，就不是故障
从某一跳开始持续全星号到结束路径在此处被拦或黑洞路由，故障点大致在这一跳附近
延迟在某一跳突然增大且不回落该链路是瓶颈（后续每跳都会带着这个增量）
单跳偶发丢包，后续跳正常多为该路由器对 ICMP 限速，不代表真实转发丢包

这几条能避开 90% 的误判：只看趋势，不看单跳。Windows 的 pathping 会对每跳发多包统计，比 tracert 更适合判断「哪一跳真的在丢包」。

四、第 ④ 层：DNS 解析链

nslookup example.com               # 交互式，Windows 自带
nslookup -type=MX example.com 8.8.8.8   # 指定记录类型与指定服务器
dig example.com +trace            # Linux：从根服务器逐级追踪权威解析
dig +short example.com A          # 只看结果，适合脚本
ipconfig /flushdns                # 清本机缓存
Get-DnsClientCache | Select Name,Data   # PowerShell 查看缓存

解析顺序是 浏览器/系统缓存 → hosts 文件 → 本地递归解析器 → 根/顶级域/权威服务器。排查时按这条链逐段切：

  • dig example.com @8.8.8.8 能解析、本机不能 → 问题在本机配置的解析器或缓存；
  • 能解析 IP 但访问错站点 → 检查 hosts、DNS 劫持、CDN 调度；
  • 解析结果TTL 很短或频繁变化 → 可能是 DNS 负载均衡，别误判成异常；
  • 开了 DoH/DoT 时，系统里看到的 DNS 配置与实际查询出口可能不一致。

五、第 ⑤ 层：端口、连接与应用

# Windows
netstat -ano | findstr :443             # 谁占用了端口；-o 显示 PID
Get-NetTCPConnection -State Established
Test-NetConnection example.com -Port 443    # 直接测 TCP 可达性
Test-NetConnection example.com -TraceRoute  # 带路径的连通性测试

# Linux
ss -tulpn                                # 监听端口
ss -tnp state established                # 已建立连接

# 通用：看 HTTP 各阶段耗时
curl -v -o /dev/null -s -w "dns=%{time_namelookup} tcp=%{time_connect} tls=%{time_appconnect} first=%{time_starttransfer} total=%{time_total}\n" https://example.com

curl -w 这一行是「网站很慢」时最有价值的一条命令：它把总耗时拆成 DNS / TCP 握手 / TLS 握手 / 首字节 / 总时间。若 dns 占大头就是解析问题，time_connect 大是网络或链路，time_appconnect 大是 TLS/证书/服务端，time_starttransfer 大则是应用处理慢。不用抓包就能把「网慢」和「服务慢」分开。

六、判断自己处在什么网络环境

要判断的事方法
延迟 / 抖动 / 丢包ping -n 50 看最小/最大/平均与丢包率；抖动 = 最大与平均之差，比单纯平均值更能反映体验
公网出口 IPcurl ifconfig.me 或 curl -s ipinfo.io/ip
是否 NAT / CGNAT对比 ipconfig 里的本机地址与公网出口：本机已是 10/172.16-31/192.168 段说明有 NAT；若运营商侧还有一层 100.64.0.0/10，即 CGNAT，无法做端口映射
是否走代理 / VPN看默认路由下一跳、netstat 里的本地代理端口、出口 IP 归属地；再对比直连与代理下的 traceroute 首跳
IPv6 是否可用ping -6 / test-ipv6.com；双栈环境下优先走 IPv6，故障时可能是 v6 单侧异常
链路瓶颈在哪pathping / mtr 看延迟突增且持续不回落的那一跳
MTU 是否被压低ping -f -l 1472 逐步下调；VPN/PPPoE 常见 1400 以下

九、边界与习惯

  • 诊断命令以只读为主。ping -f -l 65500、高频 traceroute、压力式扫描都属于对他人网络的侵扰，只在自己拥有或已获授权的环境使用。
  • 抓包（Wireshark / tcpdump）会捕获明文凭据与个人信息，留存与转发要谨慎。
  • 把每次结果连同时间戳一起记下来：间歇性故障靠单次快照永远查不出来。
  • 改动前先备份原配置；ipconfig /release、清路由、改 DNS 这类操作要能在一条命令内回滚。

高手和新手用的往往是同一批命令，差别只在顺序：先分层定位，再动手；先测 IP 后测域名；先近后远；一次只改一个变量。把这套框架记住，遇到没见过的网络环境也不会乱。
